# wx-fe 重建工作计划（以 doc/demo/茶心阁 为唯一视觉基准）

> 版本：v1.0（重建计划）  
> 目标：以 doc/demo/茶心阁 静态页面为**唯一视觉与布局基准**，重建 wx-fe 小程序（兼容 H5），做到页面结构、间距、字号、色系、圆角与组件形态逐像素对齐。

---

## 一、总体原则

1. **视觉与布局完全对齐 demo**：不做风格变体、不做“近似”。
2. **数据适配不影响布局**：接口字段不足时先用占位/兜底文案，确保结构一致。
3. **小程序 + H5 双端一致**：同一套页面与样式，必要时仅做平台兼容处理。
4. **先静态后动态**：先复刻静态结构与样式，再接入接口与交互逻辑。

---

## 二、工作分阶段计划

### 阶段 1：重建工程骨架与基础样式
- 建立新的 wx-fe 工程结构与路由（Taro + React，支持 H5）。
- 搭建全局样式层：字体、字号、行高、颜色、圆角、阴影、间距。
- 建立 demo 资源映射：图片、图标、字体、颜色变量。
- 交付物：
  - 完整工程可运行（H5 + 小程序）。
  - 全局样式文件与变量体系。
- 验收：能渲染空页面且全局样式正常生效。

### 阶段 2：核心页面静态复刻（100% 对齐）
- 按 demo 逐页复刻结构与视觉：
  - 首页（index.html）
  - 商品列表（products.html）
  - 茶间预约（tea-reservation.html）
  - 门店列表/详情（stores.html / store-detail.html）
  - 购物车/结算（checkout.html）
  - 订单列表/详情（orders.html）
- 交付物：
  - 对应页面静态结构与样式文件。
- 验收：
  - 与 demo 页面逐像素对齐（布局、字号、颜色、间距）。

### 阶段 3：组件化与复用抽象
- 将 demo 中重复结构提炼为通用组件：
  - 顶部栏、卡片、列表行、商品卡、入口宫格、TabBar 等。
- 交付物：
  - 基础组件库（仅覆盖 demo 中出现的组件）。
- 验收：
  - 页面复用组件后，视觉无差异。

### 阶段 4：数据接入与交互补全
- 按 PRD 对接接口（优先不破坏布局）：
  - 登录 / summary / 商品 / 门店 / 订单 / 购物车 / 支付。
- 缺失字段使用 demo 文案作为兜底，避免布局塌陷。
- 交付物：
  - 数据渲染后的页面与交互流程。
- 验收：
  - 功能可用且视觉对齐不被破坏。

### 阶段 5：H5 适配与小程序兼容
- H5：字体、滚动、图片尺寸与布局一致。
- 小程序：替代标签与兼容样式处理。
- 交付物：
  - H5 与小程序双端页面表现一致。
- 验收：
  - 两端无明显视觉/布局差异。

---

## 三、验收标准（必须满足）

- **逐像素对齐**：每个页面与 demo 静态页对比截图，误差极小。
- **布局一致**：结构层级、卡片数量、间距与 demo 完全一致。
- **文字一致**：字号、粗细、行高、字距与 demo 保持一致。
- **色彩一致**：背景、文字、按钮、描边颜色一致。

---

## 四、里程碑与交付顺序（建议）

1. 首页 → 商品列表 → 茶间预约
2. 门店列表/详情 → 购物车/结算
3. 订单列表/详情 → 卡券/分享/钱包等
4. 统一接入数据与交互

---

## 五、工作方式

- 每完成一个页面：
  - 以 demo 截图对比输出对照图。
  - 标注差异并立即修正。
- 所有页面通过后再进入数据接入阶段。

---

> 本计划以“demo 静态页面完全复刻”为唯一方向，不再偏离。
